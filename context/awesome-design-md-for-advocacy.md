# Design Context for Accessible Advocacy

Use these design tokens and patterns when generating or improving advocacy tools, templates, or user interfaces with AI coding agents.

---

## Core Accessibility-First Principles (Burgess-aligned)

- Prioritise high contrast and readable typography for users with visual impairments or hidden disabilities.
- Ensure keyboard navigation and screen-reader compatibility.
- Use calm, respectful, minimalist layouts — avoid overwhelming motion or dense information.
- Always include clear "human review" cues when generating forms or messages.

---

## Recommended Design Systems to Reference

- **Apple Human Interface Guidelines** — clean, accessible, calm interfaces.
- **Linear** — minimal, focused, excellent typography and spacing.
- **GitHub Primer** — clear hierarchy, accessible components.
- **Atlassian Design System** — good patterns for forms and complex workflows.

## Why This File Exists

This is a curated subset of design guidance — focused on **accessibility and calm design** — for advocacy materials generated by or with AI coding agents. It is not a full design system; it is a lightweight context file that helps AI tools produce output that respects the Burgess Principle.

For the full collection of design resources, see the [Awesome Design Tools](https://github.com/goabstract/Awesome-Design-Tools) community repository.

---

## How to Use

1. When prompting an AI agent to generate or improve advocacy templates, letters, or UI components, include relevant sections from this file in your prompt context.
2. Ensure all generated output meets the accessibility-first principles listed above.
3. Review every AI-generated artefact before sending or publishing — the "human review" step is non-negotiable under the Burgess Principle.
